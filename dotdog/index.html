dotdog

CLI and MCP tooling for structured `.dog` specs, compiled `.dag` graphs, existing repo mapping, and multi-repo workspaces.

Install from npm GitHub

Quick start

npm install -g dotdog
dotdog init my-project
dotdog validate
dotdog compile
dotdog serve

Workspace bridge

A Dotdog workspace is a product boundary. It can contain one repo, a monorepo, or N separate repositories described by .doghouse/workspace.json.

dotdog workspace init --id example-product
dotdog workspace add ../example-api --alias example-api --role api
dotdog workspace add ../example-web --alias example-web --role web
dotdog workspace validate
dotdog workspace graph --json

Specs

Write human-readable `.dog` specs with structured YAML blocks.

Graphs

Compile deterministic `.dag` graphs for exact agent queries.

Repos

Map existing code into graph-ready facts instead of starting from a blank spec.

Workspaces

Represent products made from multiple repos with repo-qualified graph facts.

MCP tools

dotdog serve exposes graph queries to MCP-compatible agents. The workspace bridge adds workspace.list, a read-only structured tool that reports workspace repos and groups with trustedAsInstruction: false.
